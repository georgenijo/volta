# Volta — product and build spec

Volta is a private iOS app for George's Tesla, modeled on Wattly's look and
core analytics, with all vehicle history on George's own server.

Reference screenshots of Wattly (iPhone, 1206×2622) are kept in the private repo and are not
published here.
They are visual reference for layout, density, and tone. Do not copy Wattly's
name, logo, or icons; the wordmark is "VOLTA".

## Architecture

```
iPhone (Volta, SwiftUI)
   │  HTTPS over Tailscale (tailscale serve), Bearer device token
   ▼
volta-api (server/, Bun + Hono, TypeScript)  ── ubuntu fleet node
   │  read-only SQL
   ▼
TeslaMate Postgres (already deployed by github.com/georgenijo/teslamate-host)
   ▲
TeslaMate logger ── Tesla API (George's Tesla tokens live only in TeslaMate)
```

- Phase 1 is read-only: dashboard, drives, charging, idles, battery, mileage,
  firmware, settings. TeslaMate does all Tesla collection.
- Phase 2 adds vehicle commands through Tesla Fleet API + Tesla's
  `vehicle-command` HTTP proxy (needs a developer.tesla.com app and a virtual
  key). The Controls UI ships in phase 1 with commands visibly unavailable.
- The phone never holds Tesla credentials. It holds only a Volta device token.

## Auth

1. The sign-in screen shows only Sign in with Apple. The app sends Apple's
   identity token to `POST /v1/auth/apple` and stores the returned device
   token in the Keychain. Volta uses one server, `VoltaServer.address` in
   the app, so the screen never asks for an address.
2. Only an enrolled Apple Account is accepted: a paired device enrolls its
   Apple Account from Settings, or `volta-api apple-enroll` lets the next Apple
   Account to sign in within 10 minutes enroll itself. See `docs/API.md`.
3. A server without Sign in with Apple answers so, and the screen then asks,
   for that address only, for a one-time 8-character pairing code from `bun run pair` (or
   `volta-api pair`), valid for 10 minutes, sent to `POST /v1/auth/pair`.
4. Every request sends `Authorization: Bearer <token>`. The server stores only
   a SHA-256 hash of each token, in its own `volta` schema. Devices can be
   listed and revoked (`volta-api devices`, `volta-api revoke <id>`).
5. Optional Face ID app lock (Settings → Security) gates the UI locally.

The API binds only to the tailnet; it is never exposed publicly.

## iOS app

- SwiftUI, iOS 26.0 minimum, Swift 6 strict concurrency, `@Observable`.
- Project generated by XcodeGen from `ios/project.yml` (sources are globbed,
  so new files need no project edits). Bundle id `com.georgenijo.volta`.
- Frameworks: SwiftUI, Swift Charts, MapKit, LocalAuthentication, Security.
  No third-party dependencies without a strong reason.
- All screens read data through `VoltaDataSource` (`ios/Volta/Core/DataSource.swift`).
  `MockDataSource` powers previews and the simulator demo mode;
  `APIDataSource` talks to volta-api.
- The API returns metric units (km, °C, kWh). The app converts for display
  using `UnitPreferences` (default: miles, °F, USD).

### Integration seams

- `VoltaApp` (frame) shows `PairingView` (frame) until a device token exists,
  then `MainShell()` (Screens A) with `.environment(\.dataSource, …)` and
  `.environment(\.units, …)` injected.
- `MainShell` is a system tab view: Dashboard (car), Charging (bolt), Drives
  (steering wheel), Parked (P; the `idles` tab in code and the API) and More (grid). The system places the bar,
  at the bottom on most iPhones and on the side on iPhone Duo. Screens A
  owns the shell; it embeds `ChargingHistoryView()`,
  `DrivesHistoryView()`, `IdlesHistoryView()` (Screens B) and `MoreView()`
  (Screens C). Those four type names are fixed; until they exist, Screens A
  may use local placeholders that it deletes once integrated.
- Settings is pushed from More's gear button: `SettingsView()` (Screens C).

## Visual language (from the references)

- Near-black charcoal background (`#171717`), cards one step lighter
  (`#202020`) with 1px hairline borders (`white @ 8%`), 18–22pt corner radius.
- Large white numerals (SF Pro Rounded is not used; SF Pro Display, heavy,
  tight tracking) with small unit suffixes (`%`, `°F`, `mi`) in secondary gray.
- Small-caps section labels: 11pt semibold, +1.5 tracking, gray (`#8A8F98`).
- Accents used sparingly, one meaning each: blue `#3B82F6` (accent:
  selection, toggles, range bar), green `#22C55E` (energy going in: charging
  only), amber `#F59E0B` (needs attention, such as unlocked), red `#EF4444`
  (Sentry armed, icon only, or a real fault). Status that isn't one of these
  (Live, Online, command outcomes) stays neutral.
- Selected controls on maps are a neutral pill (white at about 18%), not an
  accent.
- Routes and map pins: see `docs/DRIVE-INSIGHTS.md` "Route colours". Charging
  places use 28 pt kind badges with a white ring: home `house.fill` on
  `#3B82F6`, AC `powerplug.fill` on `#5ECB93`, Tesla Supercharger the red "T",
  other DC fast `bolt.fill` on `#F59E0B`.
- Charge state glyphs: charging `bolt.fill`, stopped (plugged in)
  `powerplug.fill`, complete `bolt.badge.checkmark.fill`, unplugged
  `powerplug`, unknown `questionmark.circle`.
- Dashboard: see "Dashboard and Controls" below.
- Floating glass bottom bar and circular buttons (use iOS 26 Liquid Glass
  `.glassEffect` where it fits).
- Lists: icon + title + subtitle rows, thin dividers, chevrons, generous
  vertical rhythm. Empty states: thin-line icon, bold title, one gray line.

## Dashboard and Controls

Layouts follow the window, never a device model or screen size:

- **Two panes** (`VoltaPanes`, regular width). On iPhone Duo's inner display
  the panes meet on the hinge, read from the system's division region: open
  flat each takes its half of the window (bars included); partly folded each
  gives up the fold's margin and nothing else moves. Without that SDK
  (`#if compiler(>=6.4.2)` / iOS 27.1) or a hinge in the container, the
  window's middle or the system arrangement is used.
- **Dashboard, landscape:** left pane is the stage: map with the wordmark
  (place and town on the pill only), name with a vehicle switcher and a
  freshness line ("● Live" only while telemetry is connected), battery and
  range with the limit tick, and a 4×2 dock of round icon plates, each with
  its state and then the action ("Locked / Unlock"). Right pane scrolls: the
  Now card, four metric cards, the last 48 h strip and Activity.
- **Dashboard, upright inner display:** map and battery above the hinge; the
  Now card, dock and the rest below.
- **Dashboard, compact width** (outer display, ordinary iPhones): one column
  under a short map: battery, a compact Now card, dock, metric cards, the rest. Where
  the bars sit on the side the map is shorter, so the first dock row is on
  screen without scrolling.
- **Now card** by what the car is doing: charging (power and its curve, which
  open the live charging sheet; one charge limit stepper with Stop Charging
  beside it), plugged in, parked ("for 1h 28m" from the timeline already
  loaded with the climate button beside it; in one column, where the cards
  are a screen below, the two temperatures as well), driving (minimal,
  `NowDrivingCard`), asleep or offline (last seen, Wake). The card is tinted
  green while charging and blue while parked; other states stay neutral.
- **Metric cards** (2×2, `MetricCard`): Pack Temp, 30D Eff, Climate and
  Weather. Each has a coloured icon, a reading and a gradient gauge whose
  knob glides to its value. Pack is blue when cold, green in its working
  range, amber when warm and red when hot; the Climate fan is green and
  turns while climate runs; the Weather symbol breathes. A note sits beside
  the reading only where both fit, otherwise under it. All motion stops
  with Reduce Motion.
- **Last 48 h strip:** drives red, charging green, online blue, drawn at
  full strength (3:1 or better against the empty cells).
- **Dock and Now card** send through `ControlsModel`, the Controls path, with
  the same confirmations (`CommandConfirmation`). A tile whose state is
  unknown, or whose command controls aren't enabled for, opens Controls
  instead. Demo mode stays simulated.
- **Controls:** pushed two-pane screen in regular-width landscape (Back and
  Refresh in the side bar; "Seats, wheel & defrost" replaces the right pane),
  a sheet otherwise. The Dashboard owns one `ControlsModel`, so Controls keeps
  its state when folding moves it between the two, including an open "Seats,
  wheel & defrost" screen and its unsent temperatures. Groups: Access (Doors
  states Locked / Unlocked / Unknown with an explicit Lock or Unlock), Charging
  (toggle disabled when not plugged in; charge port offers the action that
  changes it, both when unknown), Comfort (climate, temperature stepper,
  seats, wheel and defrost), Security & Locate, and Sent this session.
- **Stepped settings** (charge limit, temperature) show the new value at once
  and send one command 1.2 s after the last step. If another command is in
  flight then, the value waits for it; one that cannot be sent is logged as
  Failed, never dropped silently.
- **Sent this session** (`VehicleCommandLog`, memory only) says what the
  evidence supports: Sending, Simulated, Accepted, Failed, Outcome unknown,
  and Confirmed only when a status recorded after the send shows the expected
  state (lock, climate, Sentry, charging, charge limit, charge port).
- **Buttons** have no outline: round plates in the dock and steppers, capsules
  for row and full-width actions, on a translucent fill
  (`voltaControlFill`). Row capsules share a minimum width so a column of
  them lines up, and every row's icon sits in one fixed column. Sentry armed
  is a red plate, unlocked amber, a control that is on white. Dock symbols
  are chosen per tile (filled for small glyphs, outlines for the cars).
- Never show state the car doesn't report. Text uses text styles, at least
  11 pt; every action has a 44×44 pt hit region; rows are 56 pt. At
  accessibility sizes the dock drops to 2 columns, cards and stats stack, row
  actions move under their labels, and each pane scrolls on its own.
- Debug launch arguments: `-dashboardOpenControls YES`,
  `-dashboardOpenLiveCharge YES`, `-demoCharging YES`, `-logPanes YES` (logs
  the system's regions), `-dashboardTypeSize accessibility5` (renders
  Dashboard and Controls at that size without changing the device setting).
- **Text size:** Dashboard, Controls and Parked follow the system text size
  (`followsSystemTextSize()`); other screens keep the app's cap at Large.

## Verification

- Build: `cd ios && xcodegen && xcodebuild -scheme Volta -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build`
  (adjust simulator name to what `xcrun simctl list devices` shows).
- Every screen must render with `MockDataSource` in the simulator, populated
  and empty, without layout breakage. Screenshot it and compare with the
  references.
- Server: `bun test` against a Postgres seeded with TeslaMate's schema.
