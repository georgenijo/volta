# Volta — product and build spec

Volta is a private iOS app for George's Tesla, modeled on Wattly's look and
core analytics, with all vehicle history on George's own server.

Reference screenshots of Wattly (iPhone, 1206×2622) are kept in the private repo and are not
published here.
They are visual reference for layout, density, and tone. Do not copy Wattly's
name, logo, or icons; the wordmark is "VOLTA".

## Architecture

```
iPhone (Volta, SwiftUI)
   │  HTTPS over Tailscale (tailscale serve), Bearer device token
   ▼
volta-api (server/, Bun + Hono, TypeScript)  ── ubuntu fleet node
   │  read-only SQL
   ▼
TeslaMate Postgres (already deployed by github.com/georgenijo/teslamate-host)
   ▲
TeslaMate logger ── Tesla API (George's Tesla tokens live only in TeslaMate)
```

- Phase 1 is read-only: dashboard, drives, charging, idles, battery, mileage,
  firmware, settings. TeslaMate does all Tesla collection.
- Phase 2 adds vehicle commands through Tesla Fleet API + Tesla's
  `vehicle-command` HTTP proxy (needs a developer.tesla.com app and a virtual
  key). The Controls UI ships in phase 1 with commands visibly unavailable.
- The phone never holds Tesla credentials. It holds only a Volta device token.

## Auth

1. On the server, `bun run pair` (or `volta-api pair`) prints a one-time
   8-character pairing code valid for 10 minutes.
2. The app's pairing screen takes the server URL + code, calls
   `POST /v1/auth/pair`, and stores the returned device token in the Keychain.
3. Every request sends `Authorization: Bearer <token>`. The server stores only
   a SHA-256 hash of each token, in its own `volta` schema. Devices can be
   listed and revoked (`volta-api devices`, `volta-api revoke <id>`).
4. Optional Face ID app lock (Settings → Security) gates the UI locally.

The API binds only to the tailnet; it is never exposed publicly.

## iOS app

- SwiftUI, iOS 26.0 minimum, Swift 6 strict concurrency, `@Observable`.
- Project generated by XcodeGen from `ios/project.yml` (sources are globbed,
  so new files need no project edits). Bundle id `com.georgenijo.volta`.
- Frameworks: SwiftUI, Swift Charts, MapKit, LocalAuthentication, Security.
  No third-party dependencies without a strong reason.
- All screens read data through `VoltaDataSource` (`ios/Volta/Core/DataSource.swift`).
  `MockDataSource` powers previews and the simulator demo mode;
  `APIDataSource` talks to volta-api.
- The API returns metric units (km, °C, kWh). The app converts for display
  using `UnitPreferences` (default: miles, °F, USD).

### Integration seams

- `VoltaApp` (frame) shows `PairingView` (frame) until a device token exists,
  then `MainShell()` (Screens A) with `.environment(\.dataSource, …)` and
  `.environment(\.units, …)` injected.
- `MainShell` hosts the floating bottom bar: Dashboard (car), Charging (bolt),
  Drives (steering wheel), Idles (P), and a separate circular "…" button that
  opens More. Screens A owns the bar; it embeds `ChargingHistoryView()`,
  `DrivesHistoryView()`, `IdlesHistoryView()` (Screens B) and `MoreView()`
  (Screens C). Those four type names are fixed; until they exist, Screens A
  may use local placeholders that it deletes once integrated.
- Settings is pushed from More's gear button: `SettingsView()` (Screens C).

## Visual language (from the references)

- Near-black charcoal background (`#0E0F11`), cards one step lighter
  (`#17191C`) with 1px hairline borders (`white @ 8%`), 18–22pt corner radius.
- Large white numerals (SF Pro Rounded is not used; SF Pro Display, heavy,
  tight tracking) with small unit suffixes (`%`, `°F`, `mi`) in secondary gray.
- Small-caps section labels: 11pt semibold, +1.5 tracking, gray (`#8A8F98`).
- Accents used sparingly: blue `#3B82F6` (selection, range bar), green
  `#22C55E` (online, armed, toggles), amber `#F59E0B` (warm/warnings), red
  `#EF4444` (locked/alerts).
- Dashboard: dark 3D map at top with car marker and address pill, battery %
  + est. range, a thin blue range bar, a row of quick-control icons, 2×2
  metric cards with gradient gauges, a 48-hour activity strip, Today/7D/30D
  activity summary.
- Floating glass bottom bar and circular buttons (use iOS 26 Liquid Glass
  `.glassEffect` where it fits).
- Lists: icon + title + subtitle rows, thin dividers, chevrons, generous
  vertical rhythm. Empty states: thin-line icon, bold title, one gray line.

## Verification

- Build: `cd ios && xcodegen && xcodebuild -scheme Volta -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build`
  (adjust simulator name to what `xcrun simctl list devices` shows).
- Every screen must render with `MockDataSource` in the simulator, populated
  and empty, without layout breakage. Screenshot it and compare with the
  references.
- Server: `bun test` against a Postgres seeded with TeslaMate's schema.
